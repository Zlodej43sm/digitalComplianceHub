# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Synthetic-data POC of a bank document-review workflow (client → manager → compliance). `PROJECT_CONTEXT.md` is the detailed source of truth (workflow state machine, authorization rules, fixture policy, analysis pipeline, ops commands, known limitations) — read it before changing behavior. Only synthetic data belongs here.

## Commands

Requires Node 24 and pnpm 11.4.0.

```bash
pnpm install --frozen-lockfile
pnpm setup:local        # apply D1 migrations + seeds/local.sql to local D1 (needed before dev/smoke)
pnpm dev                # Vite + Cloudflare plugin, http://127.0.0.1:5178
pnpm typecheck          # tsc --noEmit
pnpm test               # node --test tests/*.test.*
node --test tests/workflow.test.ts            # single test file
node --test --test-name-pattern="<name>" tests/workflow.test.ts   # single test
pnpm build && pnpm smoke                      # production build + HTTP smoke
pnpm verify             # typecheck + test + build + smoke
pnpm release:check      # verify + release checks
```

Cloudflare/hosted ops (`build:cloudflare`, `deploy:cloudflare`, `seed:scenarios`, `backup/restore/reset:cloudflare`, `smoke:hosted`) are scripts in `scripts/`; see `docs/cloudflare-environments.md` and `docs/release-runbook.md`. Prettier is configured (`.prettierrc.json`).

## Architecture

- One Cloudflare Worker (`src/adapters/cloudflare/worker.ts`) serves the React SPA (`src/web/`) and the Hono API (`src/api/app.ts`). Also hosts the queue consumer and a 5‑minute scheduled outbox dispatcher.
- API/domain code depends on structural `Database` and `ObjectStore` interfaces (`src/api/types.ts`), not Cloudflare types directly. Tests run against in-memory SQLite and in-memory object stores, so business logic in `src/api/*` is testable without wrangler.
- Storage: D1 (schema via ordered SQL files in `migrations/`, add new numbered migrations rather than editing old ones), private R2 for documents (immutable, generated keys per version).
- Async analysis: upload writes document version + `analysis_jobs` + `analysis_outbox` rows; the dispatcher moves outbox rows to a Queue; the consumer runs deterministic simulated analysis (`src/api/fixture-analysis.ts`, `analysis.ts`) keyed by fixture SHA-256 hashes. Analysis never records a decision or auto-publishes text to clients.
- Uploads are restricted to the three PDFs in `fixtures/documents/` (exact filename + hash + kind; `src/api/fixture-policy.ts`). Demo scenarios live in `fixtures/scenarios.ts`.

## Key invariants

- Auth is a public fictional-account picker (no real identity). Authorization is enforced server-side per route (`src/api/authorization.ts`, `access.ts`): clients bound to one org, staff need explicit `staff_assignments` per org, `admin` has no business-data access, internal messages never reach clients, Cedar must never see Northstar data.
- Mutations require same origin plus `X-CSRF-Protection: 1`; cases carry a numeric revision and stale revisions return 409.
- Workflow transitions and rules (checklist tied to document snapshot, one final decision per case via unique constraint, Approved/Rejected read-only) live in `src/api/workflow.ts`/`cases.ts`; see PROJECT_CONTEXT.md §6.
- Wrangler configs: `wrangler.jsonc` is local; `wrangler.demo.generated.json` is generated by the cloudflare scripts — don't hand-edit.
